Page Agent

页面配置

定义要自动化操作的网页地址。可设置自动刷新间隔与网络请求捕获。

流程配置

将节点编排为顺序执行的流程。流程可在运行时接收输入，节点输出会形成流程输出并供下游节点引用。

流程组合

将多个已保存流程编排为业务流程。流程组按顺序运行流程，后一个流程自动接收上一个流程的输出。

脚本配置

自定义 JS 脚本在沙箱中执行，通过 api 对象调用全部节点能力。

脚本 API 速查 
// 页面操作：page.open(pageId) 打开页面并返回 tabId，后续操作只传 tabId
const opened = await page.open(pageId, { urlOverride, waitStable, forceReopen, maxReuseMinutes: 60 })
const tabId = opened.tabId
await page.refresh(tabId)                              // 刷新页面
await page.navigate(tabId, url)                        // 跳转地址
await page.click(tabId, '#btn')                        // 点击按钮
await page.click(tabId, { textPattern: '查询' })        // 按文本点击
await page.fill(tabId, '#input', '值')                 // 填充输入框
await page.waitFor(tabId, '.table', 15000)             // 等待元素
const t = await page.extractTable(tabId, { selector: 'table' })  // 提取表格
const s = await page.extractText(tabId, '.title')                // 提取元素文本
const r = await page.getRequests(tabId, { urlFilter: '/api/' })  // 获取请求返回
const shot = await page.screenshot(tabId)              // 截图 { dataUrl }

// HTTP / Webhook
const resp = await http.fetch(url, { method, headers, body, timeoutMs })
await http.webhook(url, { any: 'json' })               // POST JSON

// 模型调用（需在「模型配置」配置模型）
const answer = await api.model.chat('总结这段文本: ...')
const answer2 = await api.model.chat({ system: '角色设定', user: '问题', temperature: 0 })

// 运行上下文（与流程节点共享）
const v = await ctx.get('varName')                     // 读变量
await ctx.set('varName', value)                        // 写变量

// 其它
await log('消息', 'info')                               // 写日志
await sleep(1000)                                      // 等待
return result                                          // 返回值写入节点输出

定时任务

按间隔、每天固定时间或 Cron 自动触发流程，也可以定时创建并运行对话。浏览器需保持运行（扩展 Service Worker 会被 alarm 自动唤醒）。

URL 触发器

当浏览器打开匹配的页面时自动执行流程。URL 模式支持通配符 *，如 https://erp.company.com/*。

流程报告

集中查看流程与流程组的运行结果、节点统计、失败样本、warn/error 事件和可导出的流程报告。

MCP 服务器连接

管理当前扩展环境与本地 MCP 服务的连接。连接用于外部客户端配置和管理自动化流程；关闭连接后，已保存的自动化仍可独立运行。

MCP 能力与接口

            
MCP 服务器启动后同时提供三类通道：MCP 客户端通过 stdio 调用工具，浏览器插件通过 WebSocket 连接 Server，外部系统可以通过 HTTP API 触发流程。

            
    
              
  1. MCP stdio：Codex、Claude Code、Cherry Studio 等客户端通过 stdio 连接 MCP 服务器，调用下面这些工具和资源。
    2. 
              
  2. 插件 WebSocket：浏览器插件默认连接 ws://127.0.0.1:9999（可用 --ws-port 或 WS_PORT 覆盖），用于 MCP 服务器和 Extension 之间传递页面观测、操作、配置和运行请求。
    3. 
              
  3. 多插件客户端：同一个 MCP 服务器可接受多个浏览器插件连接。普通窗口和隐私窗口在 split incognito 模式下是两个独立客户端。先用 list_mcp_clients 或 GET /mcp/clients 查看 mcpClientId，再在 MCP 工具参数、HTTP header 或 query 中指定目标。
    4. 
              
  4. 能力发现：list_capabilities、list_node_catalog、get_node_type_details 用于了解可用节点和参数。
    5. 
              
  5. 配置与检索：list_context_catalog、search_context、get_context_detail 按证据缺口读取页面源、流程、流程组、运行历史等信息。
    6. 
              
  6. 页面观测：inspect_structure、inspect_element、inspect_form_fields、search_page、inspect_text、inspect_html、inspect_css、inspect_javascript 用于定位 DOM、表单、文本、样式和脚本状态。
    7. 
              
  7. 页面操作验证：act_click、act_fill、assert_element、assert_text、fill_form_fields 可先验证交互和断言，再转成流程节点。
    8. 
              
  8. 流程搭建：描述目标页面、执行步骤和输入输出，助手可以创建页面源、流程、节点和流程组。
    9. 
              
  9. 运行与验收：先观察关键节点的输入输出，再完整运行流程或流程组，根据报告确认结果。
    10. 
              
  10. 只读诊断：cdp.inspect_dom_snapshot、cdp.inspect_ax_tree、cdp.inspect_network、cdp.analyze_performance 用于补充统一感知证据；普通页面动作没有第二条 CDP 或 DOM fallback 路径。
    11. 
              
  11. 资源接口：MCP 还提供 flow://list、flow-group://list、page://list、status://current、history://runs 等只读资源。
    12. 
              
  12. HTTP API（默认启动）：Server 默认监听 http://localhost:9998（可用 --http-port 或 HTTP_PORT 覆盖），提供 GET /healthz、GET /mcp/clients、POST /webhook/run/{流程ID}、POST /webhook/run-group/{流程组ID}、GET /webhook/result/{runId}。
    13. 
              
  13. HTTP 目标选择：多客户端场景下，请求可加 header x-page-agent-mcp-client-id/x-page-agent-mcp-client-name，或 query ?mcpClientId=.../?mcpClientName=.../?incognito=true。
    14. 
              
  14. HTTP 输入参数：Webhook 请求体推荐写成 {"input":{"keyword":"测试","limit":10}}，流程节点里用 {{input.keyword}}、{{input.limit}} 取值；如果请求体没有 input 字段，则整个 JSON 会作为 input。
    15. 
              
  15. HTTP 等待参数：默认等待流程结束后返回结果；加 ?wait=false 会立即返回 runId，之后用 GET /webhook/result/{runId} 查询；加 ?timeoutMs=120000 可以调整等待超时。
    16. 
            

            
推荐流程：先说明任务和验收标准，再观察页面并保存必要节点，最后完整运行一次确认结果。

          


          

            
使用说明

            
    
              
  1. 解压插件 ZIP：开发者模式加载解压后的 page-agent-extension 目录
    2. 
              
  2. 配置 Cherry Studio：复制上方配置，把路径替换为实际解压目录
    3. 
              
  3. 启动 MCP 服务器：由 Cherry Studio 启动，或在终端运行上方启动命令
    4. 
              
  4. 开启连接：勾选上方开关，Extension 会自动连接到 MCP 服务器
    5. 
              
  5. 通过 MCP 客户端配置：在 Cherry Studio 中说"列出所有自动化能力"或"创建一个流程"
    6. 
              
  6. 配置完成后：可以关闭 MCP 服务器，插件会继续按配置运行
    7. 
            

            
注意：MCP 服务器只是配置工具，不是运行时依赖。
