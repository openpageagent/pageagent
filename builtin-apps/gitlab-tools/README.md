# GitLab 批量操作

Page Agent 内置应用，用于向多个分支 Cherry-pick 同一 Commit，或批量创建合并请求（MR）。在扩展的应用列表打开「GitLab 批量操作」。

## 连接

在右上角齿轮设置中填写站点根地址，支持 HTTP、HTTPS 和部署子路径，例如 `https://example.com/gitlab`，不含 `/api/v4`。首次使用自动打开设置。

- **浏览器登录态**：复用当前普通／无痕环境中的 GitLab 标签页，没有可用页面时创建后台标签页。尚未登录时点击「打开站点 / 登录」，登录后重新连接；操作期间保留该标签页。
- **访问令牌**：需要 `api` 范围和对应项目权限，无需登录或打开 GitLab 标签页。

点击「保存并连接」，连接成功后保存站点、认证方式和合并后删除临时源分支选项；仅勾选「记住令牌」时保存令牌到本机。已保存的可用配置在下次打开时自动连接。

## 使用

1. 选择项目，输入 Commit SHA，核对自动读取的标题和完整 SHA。项目与分支支持接口搜索、本地文本／正则过滤、手动刷新和完整分页读取；项目筛选在「筛选项目」中展开。
2. 从「可选分支」勾选并添加到「待处理分支」，也可勾选后移除。**执行覆盖待处理列表的全部分支，勾选仅用于增删。**
3. 选择操作，核对执行预览后执行。执行前会重新校验账号和 Commit。

- **创建合并请求**：从每个目标分支创建临时分支，Cherry-pick 后以 Commit 标题创建 MR，不自动合并。可在设置中启用「合并后删除临时源分支」。
- **Cherry-pick**：直接向每个待处理分支迁移 Commit。也可输入已有 MR 标题，点击「查找并替换」，将匹配的未关闭 MR 的源分支去重后替换待处理列表。

## 结果与限制

- 逐分支显示成功／失败和已创建的 MR 链接。「复制结果」按行复制各条结果，不含统计摘要。
- 单个分支失败后继续处理其他分支，并记录已完成步骤；失败时不自动清理临时分支或重试写入。网络中断后，应先在 GitLab 核实结果。
- 支持「复制后修改」：界面、客户端模块和主题原文随副本保存，可在「源码文件」页签或通过对话修改；导出携带这些文件，认证配置与令牌不随复制迁移。发布打包跳过内置应用 JS/CSS 和默认主题的压缩。
- 导出应用或全量备份时，即使选择包含业务数据，也会从导出内容中移除连接配置里的令牌，本机记住的令牌仍保留。此保护也适用于已有副本，无需重新复制；导入到其他环境后需重新配置令牌。
